# Минимальный план выполнения урока

План содержит только подзадачи, необходимые для реализации требований из
[спецификации](spec.md). Внутреннее устройство пакетов, дополнительные
инструменты и инфраструктура не являются отдельными требованиями урока.

## Задачи

### 0. [x] Создать репозиторий и зафиксировать контракт

**Результат:** отдельный репозиторий `sharetrip_notification` создан, а в
`docs/spec.md` записаны два REST-метода и схема таблицы из урока.

**Проверка:** контракт содержит `POST /notifications`,
`GET /notifications/{id}` и таблицу `notifications`.

### 1. [x] Подготовить минимально запускаемый Go-сервис

**Результат:** создан Go-модуль и точка входа приложения. Сервис может
запуститься и подключиться к PostgreSQL.

Для реализации добавляется только тот код конфигурации и подключения к БД,
который нужен следующим задачам.

**Проверка:**

```bash
go build ./...
```

После запуска приложение устанавливает соединение с доступной PostgreSQL без
ошибки.

**Зависимости:** задача 0.

### 2. [x] Добавить миграцию таблицы `notifications`

**Результат:** добавлена миграция с `CREATE TABLE notifications` точно по схеме
из `docs/spec.md`.

**Проверка:** миграция успешно применяется к PostgreSQL, после чего таблица
`notifications` существует со следующими полями:

- `id UUID`;
- `recipient_id TEXT`;
- `type TEXT`;
- `status TEXT`;
- `payload JSONB`;
- `created_at TIMESTAMPTZ`.

**Зависимости:** задача 1.

### 3. [x] Реализовать создание уведомления

**Результат:** реализован полный сценарий создания:

- HTTP-обработчик принимает `POST /notifications`;
- тело запроса соответствует контракту урока;
- уведомление сохраняется в таблицу `notifications`;
- новому уведомлению присваиваются UUID, статус `created` и время создания;
- успешный запрос возвращает `201 Created` и сохранённое уведомление;
- некорректное тело возвращает `400 Bad Request`;
- внутренняя ошибка возвращает `500 Internal Server Error`.

Модель, SQL `INSERT` и необходимое разделение кода создаются внутри этой задачи,
поскольку они нужны именно сценарию создания.

**Проверка:** тест или ручной запрос подтверждает `201` и наличие созданной
строки в PostgreSQL. Отдельно проверяются статусы `400` и `500`.

**Зависимости:** задача 2.

### 4. [x] Реализовать получение уведомления по ID

**Результат:** реализован полный сценарий получения:

- HTTP-обработчик принимает `GET /notifications/{id}`;
- сервис читает уведомление из таблицы по `id`;
- существующее уведомление возвращается с `200 OK`;
- отсутствующее уведомление возвращает `404 Not Found`;
- внутренняя ошибка возвращает `500 Internal Server Error`.

Модель ответа и SQL `SELECT` добавляются внутри этой задачи.

**Проверка:** тест или ручной запрос получает ранее созданное уведомление и
сравнивает все поля ответа. Отдельно проверяются статусы `404` и `500`.

**Зависимости:** задача 3.

### 5. [x] Проверить результат урока

**Результат:** сервис выполняет только требуемый вертикальный сценарий:

`POST /notifications → запись в PostgreSQL → GET /notifications/{id}`.

**Проверка:**

```bash
go test ./...
go build ./...
```

После применения миграции и запуска сервиса:

1. корректный POST возвращает `201`;
2. строка присутствует в `notifications`;
3. GET с возвращённым `id` отвечает `200` теми же данными;
4. предусмотренные уроком ошибки возвращают `400`, `404` и `500`;
5. в проекте отсутствуют адаптеры email, SMS, push, Telegram и других внешних
   каналов.

**Зависимости:** задачи 1–4.

## Условие завершения

Урок завершён, когда выполнены задачи 0–5. Docker Compose, Makefile,
Testcontainers, отдельный README, дополнительные API, расширенная валидация,
формат JSON-ошибок, аутентификация, метрики и трассировка для этого урока не
обязательны.
